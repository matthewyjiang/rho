# Rho configuration

Help the user configure rho. Determine what they want to change, then guide them to the right mechanism. Prefer the interactive `/config` browser or direct config-file edits over telling the user to run one-off commands, unless a command is the natural fit.

## The global `~/.rho` directory

`~/.rho` is rho's home data and settings directory. `RHO_HOME` overrides its data location, but global instructions, loose skills, and agent definition discovery still use the home-directory paths below. What lives there:

- `config.toml` - persistent settings (see below).
- `AGENTS.md` - your global instructions, applied to every session (see below).
- `agents/` - user-defined agents (for example `~/.rho/agents/planner.md`).
- `skills/` - skills available only to rho.
- `prompts/` - prompt template files; each filename becomes a slash command.
- `hooks.toml` - user hooks, always eligible.
- `models.toml` - local model catalog overrides (or the file `RHO_MODELS_PATH` selects). Use this to set a per-model `usable_context_window`, `supported_reasoning_levels`, or `catalog` slug.
- `credentials/` - secrets when the `file` credential backend is selected (`credentials/secrets.json`).
- `sessions/` - saved session transcripts and workspace keys.
- `subagents/` - global delegated runs.
- `usage.sqlite3` - the usage ledger.
- `prompt-history.sqlite3` - sent composer prompts for up-arrow recall across sessions.
- `cache/`, `web-access/`, `workflows/` - cached and runtime data; do not edit these by hand.

`RHO_HOME` also moves the usage ledger and other data roots. Credentials and the ledger live under `$RHO_HOME` too.

## The global `AGENTS.md`

`~/.rho/AGENTS.md` holds instructions that apply to every rho session regardless of project. It is loaded as a project-instruction file before any project `AGENTS.md`, so project files appear later and take precedence on conflict. Edit it to set house rules that should always apply: prose style, commit conventions, safety boundaries, build hygiene, or any standing policy. Keep it focused; everything in it is injected into the system prompt for every session.

For a quick addition in the interactive TUI, use `/remember global <text>` to append one bullet to `~/.rho/AGENTS.md`, or `/remember <text>` for the project-root `AGENTS.md` (the Git root, or the current directory outside a repository). The text must be a non-empty single line. These commands run between model turns, write the file locally, and add the instruction to the current conversation without a model response. The file is re-read when you start or switch to a different session (`/new`, `/resume` of another session, or the next launch). Global instructions stay at `~/.rho/AGENTS.md` even when `RHO_HOME` redirects data.

To revise or remove instructions, edit `~/.rho/AGENTS.md` directly with the file tools, or open it for the user and make the edit. Offer a concrete draft when the user describes a rule in prose. Project `AGENTS.md` files live at `<project>/AGENTS.md`; the global file sits in the home directory, not in any project.

For project onboarding, `/init` surveys the repository and creates or updates `AGENTS.md` at the git root (or current directory outside a repository). It preserves existing files with targeted edits and requires write permission; it is unavailable in Plan mode. Rho loads project `AGENTS.md` files from the git root through the current directory, with more specific files taking precedence. `AGENTS.md` is the only instruction filename; `CLAUDE.md` is not supported. After `/init` or any manual global/project instruction edit, run `/new` or restart Rho to reload the files. Model switches keep the cached instructions.

## Where settings live

Rho stores agent settings at `~/.rho/config.toml` by default, every key inside a table (`[model]`, `[behavior]`, `[compaction]`, `[output]`, `[web_search]`, …); a top-level key or an unknown key is a load error. A `config.toml` saved by rho 2.x is rewritten to this layout at startup, with the original kept as `config.toml.2x.bak`. The TUI reads its own display and composer settings from `~/.rho/clients/tui.toml` (top-level keys) and its theme and `[keybindings]` from `~/.rho/tui.toml`. Out-of-range values are errors, not clamped. `RHO_HOME` overrides the config directory; `rho --config <path>` loads and saves a specific file. Restart-only settings are the values the running process used at startup, so a config edit does not take effect until rho starts again. Some settings apply live; say which one you are recommending.

## The four ways to configure

1. **Interactive TUI**: in a TUI following a daemon session (`RHO_TUI_DAEMON=1`), `/config` opens the settings screen: the session's model, reasoning, fast mode, and permission mode, then the categories Models, Agent, Context, Tools, and Display. Type to filter, press `enter` to open a category or change a setting, and `esc` to return. Changes save through the daemon at once. An in-process TUI has no `/config`; use the commands below or edit the files. `/login`, `/logout`, `/model`, `/refresh-models`, and `/agents` are direct shortcuts.
2. **Command line**: `--provider`, `--model`, `--auth`, and `--reasoning` update the config file and become the future default. `rho credential-store` shows or sets the credential backend.
3. **Direct file edit**: edit `~/.rho/config.toml` by hand. Group settings by purpose. Use this for settings the TUI does not expose, such as `[model.aliases]`, `[internal_agents]` overrides, `[prompt_templates]`, `[providers.ollama].base_url` (also set by `/login ollama`), and `[providers.custom.<name>].base_url` / `catalog` / `catalog_mode` / `api` / `edit_tool` / `prompt_cache_ttl` / `request_compression` (`"zstd"` or `"gzip"`; set only when the host decodes that request encoding, such as `"zstd"` for stock CLIProxyAPI). Per-model context windows, reasoning lists, and catalog rematches live in `~/.rho/models.toml`, not `config.toml`.
4. **Environment**: `RHO_CREDENTIAL_STORE=os|file` overrides the saved credential backend; `RHO_MODELS_PATH` selects a custom models file; `RHO_TRUST_PROJECT_AGENTS=1`, `RHO_TRUST_PROJECT_HOOKS=1`, and `RHO_TRUST_PROJECT_PLUGINS=1` trust project agent definitions, hooks, and Agent Plugins.

## Inspect the current live config

Use the read-only `rho` tool with action `config` to see the sanitized live configuration (model, provider, reasoning, compaction, edit tool, web search, update checks, subagents, rtk, output limits). It excludes credentials and user content. It reports the values the running process uses; restart-only settings may differ from what is saved for the next startup.

## Common tasks

- **Set the default model or provider**: use `/model provider/model` in the TUI, or `rho --provider <provider> --model <model> --auth <auth>`. For the exact `--provider`/`--auth`/`--model` combination a provider expects, check the provider page.
- **Change reasoning**: cycle `model.reasoning` (`off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`) in `/config` under Models, or set it in config; Shift+Tab cycles the current session's level. Change `show_reasoning_output` and `zen_mode` under Display in `/config`, which saves them to `clients/tui.toml` and applies them at once; the theme is its own `/config` row and `/theme`, kept in `tui.toml` by hand.
- **Manage credentials**: `/login [provider]` and `/logout [provider]`. The credential backend is `behavior.credential_store` (`os` or `file`). When unset, rho asks where to store secrets at first login.
- **Model aliases**: define `[model.aliases]` in config and reference them with an `@` prefix, for example `model = "@deep"`. Alias values must be concrete models and cannot begin with `@`. Update the alias table in one place to change the model everywhere it is referenced.
- **Per-model context window**: edit `~/.rho/models.toml` (not `config.toml`). Example: `[models."openai-codex/gpt-5.6-sol"]` with `usable_context_window = 272000` to cap, or a larger value to raise. Restart rho or switch models after editing.
- **Internal agent models**: use `/agents`, select `session-title` or `compaction`, and press `enter` to choose a model, or edit `[internal_agents.<role>]` in config. Pick **Use conversation model** to remove an override. Plugin agents take the same `[internal_agents.<id>]` override; their picker's **Use agent default** returns to the plugin file's model.
- **Permission mode**: `behavior.permission_mode` must be `bypass`, `auto`, `allow_edits`, `plan`, or `supervised`. `allow-edits` is accepted as an alias of `allow_edits`. Set it under Agent in `/config` (the default for new sessions), with `/permissions` for the current session, or in config. `bypass` allows every capability. `auto` uses the same write and process gate as `allow_edits` and classifies only the requests that gate does not allow. `allow_edits` allows in-workspace writes to git-tracked, non-symlink files and later writes to a path already allowed this session. Untracked and gitignored paths, writes outside the workspace, and process execution still ask first. `plan` denies file writes and process execution. `supervised` asks before file writes and process execution. `/permissions` changes the current session before its next turn and clears its approvals; `/config` and the file set the default for sessions opened later.
- **Workspace rewind**: on by default for saved sessions a person prompts (the TUI, daemon sessions, `rho run`, `rho acp`). Toggle **Workspace rewind** under Agent in `/config`, or set `[behavior] workspace_rewind = false` to opt out; it applies to sessions opened afterwards. Checkpoints capture native file-tool mutations, not shell/process effects, and contain unredacted original file contents under `<session>/workspace-checkpoints/checkpoints.jsonl`. The per-file capture budget is 2 MiB (oversized files are unsupported with a notice); the serialized session journal budget is 64 MiB (a rejected append pauses capture with a visible budget notice; earlier checkpoints remain rewindable). `/rewind` restores conversation state to before the selected turn, preserving the old branch.
- **Keep cache warm**: on by default. Toggle **Keep cache warm** under Agent in `/config`, or set `[behavior] keep_cache_warm = false`. When on, the model may pass `keep_warm: true` to `process start` for a long command it will sit idle waiting on; while that process runs and the session is idle, Rho sends a one-output-token request about 30 seconds before the provider's cache TTL lapses, so the next turn re-reads the cached prompt instead of re-billing it. The status line shows `warming cache · n/max`, and ping spend appears as **Cache warm cost** in `/info`. A running turn pauses warming. The ping budget per idle stretch comes from the model's catalog cache prices: half the pings it takes for their reads to cost as much as one cache rewrite (for example 5 on GPT-5.6 or Opus, 4 on GPT-5.5; 5 when the model is unpriced), and a new turn renews it. Warming stops when the process exits or is stopped, when the budget runs out, when a ping misses the cache, when the host ignores the ping's output cap, or immediately when the setting is turned off. The `keep_warm` tool option appears or disappears on the next session. Only providers that accept a per-request output cap are warmed (OpenAI-compatible Responses hosts over HTTP; not the Codex WebSocket transport or native Anthropic yet). The cache TTL is 30 minutes on `openai` (OpenAI's documented prompt-cache lifetime) and 5 minutes elsewhere; a custom host that caches longer can declare it with `[providers.custom.<name>] prompt_cache_ttl = "1h"` (humantime duration), which also sets the idle-TTL attribution in cache miss notices.
- **Auto compaction**: under Context in `/config`; a change reaches loaded sessions at their next turn. `compaction.compact_target_percent` must stay below `compaction.compact_threshold_percent`; a value at or above it is a load error.
- **Cache miss notices**: under Display in `/config`, or `cache_miss_notices` in `clients/tui.toml`. Off by default. When on, a completed turn that re-billed a large uncached prompt (over 20K tokens or $0.10) inserts a transcript notice naming the likely cause (model switch, idle past the cache TTL, or unattributed). `/info` always reports cache hit rate and re-billed totals.
- **Header hints**: under Display in `/config`, or `show_header_hints` in `clients/tui.toml`. On by default. Off hides the keyboard hint block under the session header; a signed-out session still shows its `/login` hints.
- **Notifications**: under Display in `/config`, or `notifications` in `clients/tui.toml`. On by default. While the terminal is unfocused, an approval, questionnaire, or finished turn sends an OSC 9 desktop notification (iTerm2, WezTerm, Ghostty, kitty) or a bell (other terminals, tmux, screen). Needs terminal focus reporting (`focus-events on` in tmux). Never sent under Herdr, which shows pane state itself.
- **Web search**: under Tools in `/config`. `web_search.mode` is `auto` (native if supported, otherwise the selected backend), `backend` (force that backend), or `off`. `web_search.backend` selects `openai`, `exa`, `brave`, or `firecrawl`; failures never switch services. Each backend has its own `api_base_url`. OpenAI explicitly selects `api` or fixed-endpoint `codex`; Exa selects `api` or `mcp` with a separate `mcp_url`. Keys come from the environment (`OPENAI_API_KEY`, `EXA_API_KEY`, `BRAVE_SEARCH_API_KEY`, `FIRECRAWL_API_KEY`); keys saved by earlier versions keep working. Firecrawl Cloud requires a key; custom selfhost URLs can omit auth. Changes apply to sessions opened afterwards.
- **OpenAPI sources**: edit `[openapi.<source>]` in config with `spec` (URL or path) and usually `base_url`. Each GET and HEAD operation becomes a read-only tool found through `tool_search`; write methods are never registered. Credentials come from the environment: `auth = { type = "bearer", token_env = "..." }`, `basic` with `username_env`/`password_env`, or `api_key` with `value_env`, `in = "header"|"query"`, and `name`; `headers_from_env` maps header names to variables. A source with credentials or headers needs an HTTPS (or loopback) `base_url`, and they go only to that origin. `allow`/`deny` take globs on the operationId or `METHOD /path` (deny first); `timeout_secs` defaults to 120. A project may declare sources in `<project>/.rho/openapi.toml` but not `auth` or `headers_from_env`; they load only with `RHO_TRUST_PROJECT_OPENAPI=1`. No `${VAR}` expansion. Applies on the next session. See `/integrations/openapi`.
- **Edit tool**: under Tools in `/config`, choose `auto`, `str_replace`, or `apply_patch`. Exactly one edit schema is exposed under its own tool name (`str_replace` or `apply_patch`). `auto` keeps that preference in config and advertises the preferred format for the active provider, switching live when the provider changes. Prefer `auto` so models get the edit tool their first-party harness trained them on (Codex → `apply_patch`, Anthropic/SpaceXAI → `str_replace`), falling back to `str_replace` for everything else. The `hashline` format was removed; a config that still sets it is a load error. Pinned formats stay fixed. The change applies to sessions opened afterwards.
- **Prompt templates**: add a file under `~/.rho/prompts/` or `<project>/.rho/prompts/`, or define `[prompt_templates]` inline in config. The filename or key becomes the slash command. `$ARGUMENTS` takes all trailing text and `$1`..`$n` take positional arguments (double quotes group words); templates without placeholders get the text appended. Template files reload without a restart; inline config edits need a restart.
- **Global instructions**: add a standing rule with `/remember global <text>` between turns, or edit `~/.rho/AGENTS.md` to revise or remove rules (see above). Use `/remember <text>` for project-only instructions.
- **Keybindings**: edit `[keybindings]` in `~/.rho/tui.toml`. Values use `+`-separated modifiers and keys. `editing_mode = "vim"` in `clients/tui.toml` turns on vim-style composer editing; `/config` → Display → Editing mode sets and saves it, applying at once. Keybinding changes take effect at startup.

## Applying a change

`[questionnaire].timeout_seconds` is optional positive whole seconds. Omission disables automatic answers; zero is invalid. `/config` → Agent → Questionnaire timeout edits the same setting, with an empty field for Disabled. It applies to sessions opened afterwards. Only forms with explicit model `on_timeout` fallback answers can time out; defaults never authorize a timeout. Interaction pauses it for the rest of that form. Never use fallbacks for authorization or destructive decisions.

State which mechanism you recommend and, when relevant, when it takes effect. Settings that apply to the current session or the next turn need no restart, including `advisor_mode`, the advisor model, auto compaction, and `agent_concurrency`; most other agent settings (web search, `edit_tool`, `enable_subagents`) apply to sessions opened afterwards; inline `[prompt_templates]` and keybindings apply at startup; prompt template files reload live. The rho daemon reads a hand edit of `config.toml` on its next request, session open, or turn, so a direct edit applies like a `/config` change; an in-process TUI reads it at startup. `agent_concurrency` is under Agent in `/config` (Concurrent agents) or `behavior.agent_concurrency` in config; it defaults to 10, max 64, and applies immediately. `RHO_AGENT_CONCURRENCY` is no longer read.
